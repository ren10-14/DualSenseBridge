# ЭТАП 3 — Прототип (проверка протокола)

Этап 3 — проверка правильности протокольного ядра до интеграции с железом.
Прототип исполняется как юнит-тесты: **36 тестов, все проходят** (изначально 31 — на этапе эксплуатации добавлены тесты классификации транспорта) (см. `tests/`).

## Что проверено

### 1. CRC-32 (2 теста)
- Соответствие zlib: `Crc32("123456789") == 0xCBF43926` (стандартный тестовый вектор IEEE).
- Сидированный расчёт Sony: `zlib.crc32(b'\xA2' + …) == 0x6E578D9E` — независимо вычислено на python.

### 2. Сборка output-отчётов (3 теста)
- **BT 0x31 (78 Б)**: золотой вектор `31201003008040…9938997f` — seq=2, tag=0x10,
  flag0=0x03, моторы 0x80/0x40, CRC в [74..77] LE (seed 0xA2 по [0..73]).
- Перебор seq 0..19: seq в старшем ниббле [1] с заворотом, тег 0x10 в [2], CRC всегда валиден.
- **USB 0x02 (48 Б)**: золотой вектор `020c04…10ff20` — флаги триггеров+подсветки, RGB.

### 3. Эффекты триггеров (6 тестов)
- Feedback(3,5) = `21f8030048922400000000`, Weapon(4,7,6) = `2590000500000000000000`,
  Vibration(2,4,30Гц) = `26fc03c0b66d1b00001e00` — совпадение с независимо вычисленными векторами.
- Отклонение значений вне диапазонов (позиция > 9, сила > 8).
- **Sanitize**: 0xFD/0xFC → Off; безопасные режимы не трогаются.
- Сила 0 → Off (поведение Sony).

### 4. Разбор input-отчётов (5 тестов)
- BT 0x31: полный вектор (стики/триггеры/кнопки/hat/тач (100,200)/батарея 55% заряд/наушники) —
  все поля совпадают; повреждение тела → отклонение по CRC.
- Минимальный BT 0x01 (10 Б): раскладка по официальному дескриптору
  ([5]=hat+лицо, [6]=L1..R3, [7]=PS/тачпад, [8]=L2, [9]=R2).
- USB 0x01: общий блок, батарея.

### 5. Кадры V5 VIIPER (7 тестов)
- Кодирование золотого кадра `5650434d0581030007000000cf395a5f`+payload (CRC по [4..11]+payload).
- Round-trip encode/decode (тип, seq, payload, consumed).
- Полный кадр отдачи 474 Б; битый CRC → флаг broken (по контракту V5 — разрывать соединение);
  чужая магия → broken; неполный кадр → ожидание (не broken); два кадра в буфере подряд.

### 6. Трансляция отдачи (7 тестов)
- **Native**: из USB-отчёта игры (флаг только 0x01) → патч HAPTICS_SELECT → 0x03;
  отладочный режим триггера 0xFD → Off (флаг сохранён); пустая отдача → null (не отправляем);
  RumbleScale 0.5 → моторы 0x80/0x40 → 0x40/0x20.
- **Structured**: сборка из полей (rumble+RGB+playerLeds+Weapon R2) с корректными флагами.
- **InputMapper**: стики 0..255 → -128..127, hat 5 (ЮЗ) → Down|Left, кнопки → uint32 LE
  в wire-байтах, тач/IMU; нейтральный hat → 0; golden BT input → wire end-to-end.

## Найденные и исправленные ошибки (главная ценность этапа)

1. **Смещения input-блока**: gyro/accel/timestamp/тач/батарея были смещены — исправлены по
   hid-playstation.c (gyro +15, accel +21, timestamp +27, тач +32, статус +52/+53).
2. **Минимальный BT-отчёт**: раскладка была неверной — исправлена по официальному дескриптору.
3. **CRC кадров V5**: CRC покрывает [4..11]+payload **через** поле CRC (несмежные участки) —
   нужен каскадный расчёт, а не один спан.
4. **USB output 48 vs 63**: Linux паддит до 63, но Windows требует ровно 48 (по дескриптору) —
   подтверждено свежим кейсом (upshift PR #11, сентябрь 2026) и controllers.fandom.
5. **Исключения HidSharp 2.6.4**: публичного `HidSharpException` нет (DeviceIOException —
   internal); ловим IOException/ObjectDisposedException/UnauthorizedAccessException.

Вывод: протокольное ядро полностью подтверждено независимыми векторами — можно строить
интеграцию (ЭТАП 4).
