# DualSenseBridge

**Windows-приложение (один EXE), которое «проксирует» физический геймпад Sony DualSense, подключённый по Bluetooth:**

- игре показывается **виртуальный контроллер типа DualSense** (не Xbox 360!) — со всеми нативными возможностями;
- обратная связь игры — **адаптивные триггеры (R2/L2), вибрация, RGB-подсветка, player LED** — перехватывается и **корректно транслируется** в настоящий HID-протокол физического DualSense по Bluetooth;
- физический геймпад скрыт от игр (HidHide), чтобы не было двойного ввода.

```
┌─────────────┐  HID   ┌────────────┐  USB(virtual) ┌───────────────┐  TCP :3242 ┌─────────────────┐
│ DualSense   │◄──BT──►│ DualSense  │◄──────────────│  VIIPER +     │◄───────────│  DualSenseBridge │
│ (Bluetooth) │ 0x31   │ Bridge     │   usbip-win2  │ виртуальный   │  V5-стрим  │  читает ввод,     │
└─────────────┘        └────────────┘               │ DualSense     │            │  пишет отдачу     │
                                                     └───────────────┘            └─────────────────┘
```

## Почему не Xbox 360 (ViGEm)?

Эмуляция Xbox 360 означает XInput: игры видят «обычный» геймпад и присылают только простую вибрацию. **Адаптивные триггеры и подсветка в XInput отсутствуют** — обратная отдача DualSense была бы потеряна. Поэтому мост создаёт виртуальный контроллер **именно типа DualSense** (VID 054C / PID 0CE6) — игры и Steam Input работают с ним как с настоящим DualSense и используют полный набор эффектов.

## Компоненты и лицензии

| Компонент | Роль | Лицензия |
|---|---|---|
| DualSenseBridge (этот проект) | мост ввода/отдачи, трей, CLI | — |
| [VIIPER (форк hbashton)](https://github.com/hbashton/VIIPER) | виртуальные HID-устройства, в т.ч. «DualSense V5» с триггерами; ставится как отдельный процесс | GPL-3.0 (отдельный процесс — допустимо) |
| [usbip-win2 (vadimgrn)](https://github.com/vadimgrn/usbip-win2) | проброс виртуального USB на localhost | BSD-2-Clause, подписан Microsoft |
| [HidHide (Nefarius)](https://github.com/nefarius/HidHide) | скрытие физического геймпада от игр | MIT |
| HidSharp | доступ к HID из .NET | Apache-2.0 |

Всё устанавливается локально, без облака. Обход DRM/античитов не выполняется: приложение лишь перенаправляет HID-потоки, как это делают DS4Windows/Steam Input.

## Быстрый старт

1. Соберите EXE: `powershell -ExecutionPolicy Bypass -File build.ps1` (нужен .NET SDK 10).
2. Запустите `DualSenseBridge.exe` и нажмите кнопку **«Установить зависимости (автоматически)»**
   (или `DualSenseBridge.exe --install-deps`) —
   - **viiper.exe уже вшит внутрь EXE** (hbashton/VIIPER v0.1.2, GPL-3.0, отдельный процесс):
     приложение само распаковывает его в `%LOCALAPPDATA%\DualSenseBridge` и запускает скрытым;
     скачивать ничего не нужно;
   - **usbip-win2** ставится ровно в версии **0.9.7.7** — той, которую требует viiper
     (проверено по его бинарнику; при другой версии viiper отказывается стартовать);
     если у вас другая версия — установщик заменит её (UAC, возможна перезагрузка);
   - **HidHide** — опционально (тихая установка, UAC).
   Всё по HTTPS только с официальных репозиториев.
3. Подключите DualSense по Bluetooth. Мост запустится автоматически
   (программа проверяет готовность зависимостей каждые 15 с).

Приложение появится в трее: статус компонентов, тесты эффектов, статистика пакетов, журнал, настройки.

## Если «контроллер не найден» (диагностика)

1. **`DualSenseBridge.exe --list-devices`** — покажет все HID-устройства и подсказки.
2. Физический контроллер виден в окне программы **даже без установленных зависимостей**
   (строка «Физический контроллер: виден … — мост не запущен»); тесты эффектов
   (вибрация/триггеры/подсветка) работают сразу, без VIIPER.
3. Контроллер подключён, но не виден программе:
   - он скрыт через HidHide (например, другой программой) → `DualSenseBridge.exe --unhide-device`;
   - занят приложением с эксклюзивным доступом → закройте его.
4. Транспорт (Bluetooth/USB) определяется автоматически по формату input-отчётов:
   BT = 0x31 (78 Б) или минимальный 0x01 (10 Б), USB = 0x01 (64 Б). В журнале видно
   строку «Транспорт уточнён по input-отчёту …».
5. Мост не запускается? Нужны **usbip-win2 + viiper.exe** — кнопка «Установить
   зависимости…» в окне или меню трея; программа проверяет их каждые 15 с и
   запускает мост автоматически, как только они появятся.

## CLI-флаги

```
DualSenseBridge.exe                 — запуск GUI (трей)
  --verbose                         — подробный лог в консоль
  --log-file <путь>                 — лог в файл (по умолчанию %APPDATA%\DualSenseBridge\log.txt)
  --console                         — консольный режим без GUI
  --list-devices                    — список HID-устройств (DualSense помечается)
  --test-rumble                     — тест вибрации на физическом контроллере
  --test-triggers                   — тест адаптивных триггеров R2/L2
  --test-led                        — тест подсветки и player LED
  --hide-device | --unhide-device   — скрыть/показать физический контроллер (HidHide)
  --install-deps | --check-deps     — установка/проверка драйверов
  --mode native|structured          — режим трансляции отдачи (по умолчанию native)
  --dialect hb|upstream             — диалект VIIPER (по умолчанию hb = триггеры)
  --version                         — версия
```

## Как это работает (кратко)

1. **Ввод**: физический DualSense по BT шлёт input-отчёты 0x31 (78 Б, CRC32). Мост разбирает их и отправляет в VIIPER (33-байтовый wire-формат виртуального DualSense).
2. **Отдача**: игра пишет output-отчёт в виртуальный DualSense; VIIPER пересылает его мосту кадром 0x81 (474 Б). Мост извлекает нативный 47-байтовый общий блок, применяет патчи безопасности и оборачивает его в BT-отчёт 0x31 (78 Б, seq + магический тег 0x10 + CRC32) для физического контроллера.
3. **Оптимизация пакетов**: очередь newest-wins + дедупликация неизменённых отчётов + минимальный интервал записи 4 мс (период опроса BT). Содержимое протокола не обрезается.
